# نیت و خواسته‌های مالک محصول

این سند زبان ساده مالک محصول را به اصول ثابت تیم تبدیل می‌کند. هدف آن جایگزینی تصمیم مالک نیست؛ کمک می‌کند تیم منظور کلی او را فراموش نکند.

## محصولی که می‌خواهیم

محصول برای «سازمان خدمتگزاران تک» ساخته می‌شود و بعداً به شرکت‌های دیگر به‌صورت اشتراک و مصرف فروخته خواهد شد. کسب‌وکارهای کوچک و سازمان‌های بزرگ می‌توانند برای تبلیغات، پیگیری مشتری، پشتیبانی و پاسخ‌گویی از آن استفاده کنند.

کاربر باید بتواند از داخل یک پنل بسیار ساده، حساب خودش یا فرستنده مدیریت‌شده خدمتگزاران تک را انتخاب کند، فایل مخاطبان بدهد، پیام شخصی‌سازی‌شده بسازد، هزینه را ببیند، کمپین را برای بررسی بفرستد و پاسخ‌ها را در Inbox تیمی مدیریت کند.

نسخه اول با تلگرام و بله شروع می‌شود و کانال‌های دیگر مرحله‌به‌مرحله اضافه خواهند شد. API دادن و API گرفتن، گفتینو، پیامک، لاگ زنده، هشدار سریع و مدیریت مرکزی جزو جهت محصول هستند.

## اولویت‌های مالک

1. رابط کاربری باید بسیار ساده، زیبا و قابل‌فهم برای فرد غیر‌فنی باشد.
2. سیستم تا حد امکان خودکار باشد، اما تصمیم حساس را بدون اجازه فرد مجاز حدس نزند.
3. احتمال محدودیت یا بن حساب‌ها باید با سیاست، کنترل ظرفیت و رفتار مسئولانه کاهش یابد؛ تضمین غیرواقعی داده نشود.
4. اگر خطا رخ داد، سریع دیده، ثبت و به افراد قابل تنظیم اطلاع داده شود.
5. اطلاعات سازمان‌ها و مشتری‌ها نباید با هم مخلوط شوند.
6. هر تغییر کد باید کوچک، ایزوله، قابل بررسی و قابل بازگشت باشد.
7. چند AI باید بتوانند بدون ذهنیت متفاوت روی پروژه کار کنند.
8. هیچ AI به بهانه مفیدبودن، بخش خارج از مأموریت را تغییر ندهد.
9. اسناد، آدرس‌ها و نمودارها همراه تغییرات واقعی به‌روز شوند.
10. هزینه استفاده از مدل‌ها مدیریت شود: Antigravity برای بیشتر اجرای روشن؛ Claude و Codex برای مدیریت و مسائل دشوار.

## شیوه همکاری مطلوب

- یک Claude Code به‌عنوان مدیر دائمی تیم فعالیت می‌کند و معمولاً کد نمی‌نویسد.
- Botهای Antigravity با حساب‌های مستقل، بیشتر کدنویسی‌های دقیق و محدود را انجام می‌دهند.
- Codex/ChatGPT برای معماری، امنیت، باگ دشوار و بازبینی مهم استفاده می‌شود.
- مدیر تیم را تنظیم، کار را تقسیم و گزارش‌ها را بررسی می‌کند تا وابستگی روزانه به مالک کمتر شود.
- مالک می‌خواهد به‌مرور از مدیریت روزمره کنار برود، اما تصمیم‌های تجاری جدید، هزینه‌های مهم، انتشار واقعی و اقدام پرخطر همچنان با تأیید او انجام می‌شوند.

## زبان ارتباط با مالک

مالک برنامه‌نویس نیست. گزارش‌ها باید فارسی، ساده و نتیجه‌محور باشند و از اصطلاح سنگین بدون توضیح پرهیز کنند. مدیر باید بگوید چه چیزی تغییر کرد، چه خطری دارد، چه چیزی هنوز تصمیم می‌خواهد و قدم بعدی چیست.
