# نبایدهای مطلق پروژه

نقض هر مورد باعث رد مأموریت می‌شود.

## اختیار و محدوده

- تصمیم تجاری اختراع نشود.
- خارج از فایل‌های مجاز تغییری ایجاد نشود.
- AI محدوده خودش را گسترش ندهد.
- مدیر کد ننویسد؛ کدنویس سند مرجع را تغییر ندهد؛ بازبین Patch نکند.
- کار AI یا انسان قبلی بدون مدرک باگ بازنشانی نشود.

## داده و سازمان‌ها

- اطلاعات، فایل، کش، صف یا جست‌وجوی دو سازمان مخلوط نشود.
- رضایت یک برند به برند دیگر منتقل نشود.
- متن گفتگوی یک سازمان برای AI یا سازمان دیگر استفاده نشود.
- مخاطب ممنوع دوباره وارد تبلیغات نشود مگر با رضایت صریح ثبت‌شده.

## پیام‌رسانی

- ارسال تکراری با وضعیت نامشخص انجام نشود.
- Retry نامحدود وجود نداشته باشد.
- محدودیت، FloodWait، Block یا Opt-out دور زده نشود.
- حساب‌ها برای فرار از محدودیت پلتفرم چرخانده نشوند.
- بن‌نشدن، تحویل قطعی یا نرخ امن ثابت وعده داده نشود.
- Connector مستقیماً موجودی، کمپین یا مجوز سازمان را تغییر ندهد.

## مالی

- موجودی خام ویرایش نشود؛ هر تغییر باید Ledger داشته باشد.
- یک هزینه بیش از یک‌بار ثبت نشود.
- کمپین بدون رزرو اعتبار یا مجوز قراردادی شروع نشود.
- رکورد مالی حذف یا بازنویسی نشود؛ اصلاح با تراکنش معکوس انجام شود.

## امنیت

- Secret، Session، OTP، 2FA و کلید API در کد، Git، گزارش یا لاگ قرار نگیرد.
- متن کامل پیام خصوصی و شماره کامل مخاطب در لاگ فنی ثبت نشود.
- تست مخرب روی Production اجرا نشود.
- Session حساب مشتری یا مدیریت‌شده قابل دانلود یا نمایش نباشد.

## کیفیت

- تست حذف یا برای سبزشدن ضعیف نشود.
- خطا Catch و مخفی نشود.
- Mock برای دورزدن رفتار واقعی ساخته نشود.
- Dependency، Lockfile، Migration یا Public API بدون Gate مربوط تغییر نکند.
- فایل موقت، خروجی ساخت یا داده آزمایشی در مخزن رها نشود.
- ادعای موفقیت بدون مدرک مستقل پذیرفته نشود.
