# مدل همکاری تیم هوش مصنوعی

## ساختار تیم

- یک Bot با موتور Claude Code، مدیر و Chief تیم است.
- مدیر کدنویسی محصول نمی‌کند؛ کار را تحلیل، کوچک، قراردادی و واگذار می‌کند.
- Codex و Antigravity نقش کدنویس یا بازبین مستقل دارند.
- یک Bot نمی‌تواند هم مجری و هم بازبین نهایی همان مأموریت باشد.
- مالک محصول تأییدکننده تصمیم‌های تجاری و تغییرات پرخطر باقی می‌ماند.

## حساب‌های متعدد Antigravity

- هر حساب Google Pro به‌صورت Engine Instance مستقل در MausBot ثبت می‌شود.
- برای هر حساب یک Bot کدنویس مشخص ساخته می‌شود؛ مانند `antigravity-dev-01` و `antigravity-dev-02`.
- Session، تنظیمات و محدودیت مصرف حساب‌ها با یکدیگر مخلوط نمی‌شوند.
- تعویض حساب وسط اجرای یک مأموریت ممنوع است.
- اگر یک حساب محدود شد، مدیر پس از ثبت وضعیت، مأموریت را از آخرین Commit سالم به Bot دیگری واگذار می‌کند.
- دورزدن محدودیت ارائه‌دهنده مجاز نیست؛ حساب جایگزین فقط طبق اشتراک و شرایط معتبر خودش استفاده می‌شود.

## جداسازی محل کار

هر Bot کدنویس باید پوشه یا Worktree جدا داشته باشد. دو Bot حق ندارند هم‌زمان در یک Working Folder بنویسند.

نمونه نام‌گذاری:

```text
manager-claude        -> فقط مدیریت و اسناد مأموریت
developer-codex-01    -> شاخه اختصاصی مأموریت
developer-ag-01       -> حساب Antigravity اول
developer-ag-02       -> حساب Antigravity دوم
reviewer-codex-01     -> بازبینی بدون اصلاح کد
```

## جریان هر مأموریت

1. مدیر فایل قرارداد را می‌سازد و محدوده را مشخص می‌کند.
2. مدیر یک کدنویس آزاد انتخاب می‌کند.
3. کدنویس در شاخه و پوشه جدا اجرا و گزارش می‌کند.
4. بازبین مستقل Diff و شواهد را بررسی می‌کند.
5. مدیر نتیجه را قبول، رد یا برای اصلاح برمی‌گرداند.
6. فقط تغییر تأییدشده وارد شاخه اصلی می‌شود.

## GitHub به‌عنوان مرجع مشترک

- شاخه `main` نسخه معتبر و محافظت‌شده است.
- هیچ کدنویسی مستقیماً روی `main` کار نمی‌کند.
- هر مأموریت یک شاخه با شناسه Task دارد.
- Pull Request محل بررسی تغییر، تست و رأی مدیر است.
- چت MausBot حافظه اجرایی است؛ تصمیم معتبر باید در سند یا Task داخل Git ثبت شود.

## مجوزهای پیشنهادی MausBot

- مدیر: خواندن کل اسناد، ساخت Task، واگذاری، مشاهده گزارش و مدیریت اعضای تیم؛ بدون اختیار کدنویسی یا Merge خودکار.
- کدنویس: فقط Working Folder و مسیرهای قرارداد؛ بدون Secret تولید، سرور واقعی و شاخه اصلی.
- بازبین: خواندن Diff و اجرای تست‌های غیرمخرب؛ بدون ویرایش کد.
- حالت عادی Approval فعال است. Full Access عمومی برای تیم ممنوع است.

## برخورد با محدودیت یا قطع موتور

- کار نیمه‌تمام از روی حدس ادامه داده نمی‌شود.
- آخرین Commit سالم، گزارش اجرا و موارد باقی‌مانده ثبت می‌شوند.
- مدیر Bot جایگزین را انتخاب و همان قرارداد یا نسخه جدید آن را واگذار می‌کند.
- تاریخچه چت به‌تنهایی برای تحویل کافی نیست؛ وضعیت باید در فایل‌های Task ثبت شده باشد.
